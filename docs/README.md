## 冪等性（v1.2 で実測・GUI 版 §8.6）

同じ操作が繰り返される GUI では、DD-001 が掲げた「冪等・再現可能」という目標が CLI 版より重要になる。**実測の結果、rclone の API は一様に冪等ではない。**

- **冪等**: `mount/unmountall` / `options/set` → 終了時・切替時は個別 unmount のループではなく `unmountall` を使う
- **非冪等（成功扱いにする）**: `mount/mount` の `already mounted`、`mount/unmount` の `mount not found` → **どちらも「望む終了状態にすでに達している」ことを示すため、エラーにしない**
- **CRIT-03**: `--rc-addr 127.0.0.1:0`（本アプリの既定）では **rcd を二重起動しても別ポートで両方立ち上がる**。**プロセスの単一性はアプリが担保する**（PID ファイル + 孤児の回収 + 単一インスタンス化 + 終了時削除の 4 点セット）

## 重要な前提（見落としやすい）

- **public バケットは秘匿性ゼロ。** key を知れば誰でも読める。削除ではなく `gone/` へ移動する（DD-001 §4.4）
- **public は read-only でマウントされる**（GUI 版 G-08・実測で成立を確認）。公開は必ずアプリの共有ダイアログを通るため、Exif 除去・slug 化・上書き確認を迂回できない
- ただし **OS レベルでは read-only ボリュームにならない**（GUI 版 F-01）。**Finder は書けると認識してドラッグを許可し、そのあと失敗する。** 安全性は達成されるが、UI 側の案内が必須
- **接続テストの「全項目 ✓」には公開 URL の実到達確認が含まれる**（GUI 版 §4.4 手順 5）。カスタムドメイン未接続を、共有相手に 404 を渡す前に検出する
- **保存 ≠ 即クラウド同期。** VFS write-back により反映は約 30 秒以内。GUI 版はこれを「未送信 N 件」として可視化する
- **単一利用者・単一編集端末・常時接続が前提。** localhost NFS は認証なしで待ち受けるため、共有 Mac では使用しない（DD-001 SEC-09）
- **疎通確認にバケット名なしの列挙を使わない。** バケットスコープトークンでは失敗し、正しいトークンを「不良」と誤診断する（DD-001 F-01 / GUI 版 §4.4 MUST）
