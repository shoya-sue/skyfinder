Cloudflare R2 × macOS Finder マウント
＋ 外部公開ストレージ 詳細設計書

R2 バケットを Mac の Finder にネイティブドライブとして常時マウントし、同一基盤から任意ファイルを外部公開（恒久 URL／期限付き URL）できる個人ストレージシステムの完全設計。実装エージェントが本書のみを入力として、追加の判断なしに構築を完了できる粒度で記述する。

Mount Method
rclone nfsmount（kext 不要）
Publish Method
R2 カスタムドメイン + presigned URL
Target OS
macOS 14+ / Apple Silicon
月額コスト目安
〜100GB で $1.35/月（egress $0）

§00 結論（TL;DR）

  1. マウント方式は rclone nfsmount を採用する。macOS 内蔵 NFS クライアント経由でマウントするため macFUSE（kext）も FUSE-T も不要。Apple Silicon でセキュリティ設定の変更が一切不要であり、launchd で常駐化する。
  2. バケットは private / public の 2 バケット物理分離とする（flab-stor-private / flab-stor-public）。カスタムドメイン公開はバケット全体に効くため、prefix 分離では誤公開リスクを排除できない。Finder には 2 つのドライブとして両方マウントする。
  3. 恒久公開は files.fracturelab.dev（R2 カスタムドメイン）。public バケットに置いたファイルは即座に https://files.fracturelab.dev/<key> で公開される。r2.dev サブドメインはレート制限付きのため開発確認専用。
  4. 期限付き共有は presigned URL。rclone link --expire 24h 一発で private バケット内ファイルの時限 URL を発行できる（S3 API ドメイン経由・カスタムドメイン不可という制約あり）。
  5. フォーマット（構成規約）: キーは NFC 正規化 UTF-8・ASCII 推奨、public バケットは {カテゴリ}/{YYYY}/{slug}.{ext}、private は用途 prefix（vault-backup/ 等）。.DS_Store / ._* はマウント側で exclude する。画像の公開は r2share pub 経由とし、Exif（GPS 等）を自動除去してからアップロードする（SEC-08）。
  6. ロードマップは 4 フェーズ・正味 3〜4 時間: P0 R2 準備(30m) → P1 マウント+常駐化(60m) → P2 外部公開(45m) → P3 共有 CLI+運用整備(60m)。P3 の Worker プロキシ（認証付き配信）はオプション。
§0.5 実装前・認識合わせ確定事項（v1.4 追記 — 外部監修 codex / grok の収束指摘を集約）

以下は新規の設計変更ではなく、本書に既述の前提のうち実装者が見落としやすい要点の集約である。着手前に必ず本節を読むこと。各項の詳細は指示先の節に従う。

  1. public は秘匿性ゼロ。key を知れば誰でも読める。公開後は key 不変・削除でなく gone/ へ移動（§4.4 / §7.1 CAUTION）。機微情報は絶対に public へ置かない。
  2. 画像公開は原則 r2share pub 経由。Finder で public へ直置きすると Exif（GPS 等）除去が働かない（SEC-08 / §8.3）。直置き時は手動 exiftool -all= を要する。設計上「D&D で即公開」と衝突する最大の運用リスク。
  3. 保存 ≠ 即クラウド同期。VFS write-back（15s + 転送）で反映は「約 30 秒以内」。書込み直後の電源断でキャッシュ中データは失われ得る（R-03 / D-05）。
  4. 単一利用者・実質単一編集端末・常時接続が前提。localhost NFS は認証なし待受のため、共有 Mac・ゲスト有効環境では本方式を使用しない（SEC-09 / R-04 / R-06）。前提が変わる場合は本書の改版を要する。
  5. 疎通確認に rclone lsd r2: を使わない。必ずバケット名付き（rclone lsd r2:flab-stor-private 等）。バケットスコープトークン（D-06）では ListBuckets が失敗し「トークン不良」と誤診断する（§6.2 / T-01 / F-01）。
  6. 変更してよいのはプレースホルダ 4 つのみ（§14.1）。バケット名・ドメイン・マウントパス・launchd Label・マウントフラグは固定。逸脱は本書の改版が先（チューニングは §6.5 の許容範囲のみ）。

再マウント挙動の注記: launchd の再起動は異常終了時のみ（KeepAlive.SuccessfulExit=false）。Finder で「取り出し」た場合は exit 0 のため自動復帰しない。復帰は launchctl kickstart gui/$(id -u)/dev.fracturelab.r2mount.private（§6.4）。

01. 目的・スコープ

1.1 目的

  • Cloudflare R2 を Finder からドラッグ&ドロップで扱える常設ネットワークドライブとして利用可能にする（読み書き両対応）。
  • 同じ基盤から、ファイル単位で (a) 恒久公開 URL と (b) 期限付き共有 URL を発行できるようにする。
  • egress 無料という R2 の特性を活かし、Dropbox / Google Drive 的な用途（配布・バックアップ・素材置き場）を 従量 $1〜2/月クラスで実現する。

03. 技術選定と決定事項

実装エージェントは本節の決定 D-01〜D-07 を変更してはならない。比較根拠は監査可能性のために残す。

3.1 D-01: Finder マウント方式 → rclone nfsmount

候補仕組みkext / 追加SW評価判定
rclone nfsmount rclone が localhost に NFS サーバを立て、macOS 内蔵 NFS クライアントでマウント 不要 Apple Silicon でセキュリティ設定変更ゼロ。rclone 本体のみで完結。VFS キャッシュ全機能利用可 採用
rclone mount + macFUSE カーネル拡張(kext)による FUSE kext 要 Apple Silicon ではリカバリモードで「低セキュリティ+kext 許可」が必要。OS アップデート毎に壊れる前科多数 不採用
rclone mount + FUSE-T ユーザ空間 FUSE（NFS/SMB/FSKit バックエンド） FUSE-T 要 kext 不要だが追加依存が 1 つ増える。NFS バックエンドには「Finder で見るだけで mtime が書き換わり再アップロードが走り得る」既知問題。FSKit バックエンドは macOS 26+ 限定で成熟待ち 不採用
(将来再評価)
Mountain Duck 商用 GUI（内部で FUSE-T 相当） 購入 ($39) GUI は快適だが、launchd/スクリプトによる自動化・キャッシュ挙動の厳密制御ができない。CLI 統一方針に反する 不採用
Cyberduck / Transmit 転送クライアント（マウントではない） — 「Finder に常設ドライブ」という要件を満たさない 対象外
NOTE — 将来の乗り換え線
macOS 26 以降で FSKit（Apple 純正のユーザ空間ファイルシステム基盤）対応が rclone / FUSE-T 側で安定した場合、nfsmount から rclone mount -o backend=fskit 系へ移行するとパフォーマンスと Finder 統合が向上する可能性がある。本設計はマウントコマンド 1 行の差し替えで移行可能な構造（§6.3 で mount コマンドを変数化）とする。

3.2 D-02: バケット構成 → private / public の 2 バケット物理分離

  • R2 のカスタムドメイン公開・r2.dev 公開はバケット単位で有効化される。単一バケット + prefix 運用では「公開設定を入れた瞬間に全 prefix が公開」となり、誤公開の構造的リスクを持つ。
  • 2 バケットなら「public バケットに入れたものだけが公開される」という物理的な保証になり、Finder 上でもドライブが分かれるため人為ミスが起きにくい。
  • デメリット（バケット間移動がサーバサイドコピー+削除になる）は §8 の r2share pub で吸収する。

3.3 D-03〜D-07: その他の決定

ID決定事項理由
D-03恒久公開はカスタムドメイン files.fracturelab.dev。r2.dev は開発確認専用r2.dev はレート制限ありで本番非推奨（Cloudflare 公式見解）。カスタムドメインは Cache Rules / WAF / アクセスログが使える
D-04期限付き共有は presigned URL（S3 API ドメイン経由）サーバ不要・即発行・失効自動。カスタムドメインでは使えない制約は許容（共有 URL の見た目より運用コストゼロを優先）
D-05VFS キャッシュモードは --vfs-cache-mode fullFinder / 各種アプリのランダム書込み・プレビュー生成に耐えるのは full のみ。writes 以下では動作しないアプリが多い
D-06API トークンは「バケットスコープの Object Read & Write」を Mac 用に 1 本。Admin 権限トークンは発行しないMac 側漏洩時の影響半径をオブジェクト操作のみに限定（バケット削除・公開設定変更は不可能にする）
D-07location hint は APAC利用者（東京）からの書込みレイテンシ最小化。R2 は自動配置だがヒントで初期配置を寄せる

04. フォーマット設計（バケット・キー・命名規約）

「どんなフォーマットを形成すれば対応可能か」への回答。ここで定義する規約は Finder 上のフォルダ構造にそのまま写像される。

4.1 バケット命名

バケット名用途公開設定マウント先
flab-stor-private私有領域（デフォルトの置き場）なし（非公開）~/R2/private
flab-stor-public公開領域custom domain 有効~/R2/public

命名規則: 小文字英数とハイフンのみ・3〜63 文字・作成後変更不可。flab- prefix は fracturelab 系リソースの共通 prefix として予約する。

4.2 オブジェクトキー規約（必須ルール）

IDルール理由
K-01文字集合: a-z 0-9 - _ . / を推奨。日本語キーは private バケットのみ許容し、public バケットでは禁止公開 URL のエンコード事故・リンク切れ防止
K-02Unicode 正規化は NFC。rclone 側は --no-unicode-normalization=false（デフォルト）を維持するmacOS は NFD を返すことがあり、正規化を切ると同名別ファイルが発生する
K-03先頭 / 禁止・連続 // 禁止・末尾 / はディレクトリマーカーとして rclone に任せる（手動生成しない）S3 系ストレージの疑似ディレクトリ仕様との整合
K-04.DS_Store, ._*, .Spotlight-V100, .Trashes はバケットに保存しない（マウント側 exclude で強制、§6.3）ノイズ抑制・Class A 操作課金の抑制
K-051 オブジェクト ≦ 300GB を上限とする（R2 の上限は約 5TB だが運用上限として設定）マルチパート再送コストとキャッシュディスク圧迫の抑制

4.3 private バケット prefix レイアウト

flab-stor-private/
├── inbox/                  # 一時置き場。月次で整理（Obsidian 00_inbox と同思想）
├── vault-backup/           # Obsidian vault 等のバックアップ
│   └── {YYYY-MM-DD}/       # 日付スナップショット単位
├── projects/
│   └── {project-slug}/     # 例: partscraft/, living-character/
├── media-src/              # 公開前の元素材（動画・PSD 等の重量級）
└── share-staging/          # presigned 共有する前提のファイル置き場

4.4 public バケット prefix レイアウト（＝公開 URL 設計）

flab-stor-public/
├── assets/{YYYY}/{slug}.{ext}     # 汎用配布物 → files.fracturelab.dev/assets/2026/foo.zip
├── img/{YYYY}/{slug}.{ext}        # 画像。ブログ・SNS 貼付用
├── releases/{product}/{semver}/   # 例: releases/partscraft/0.3.0/partscraft-0.3.0.tgz
└── pub/                           # その他雑多な公開物（原則ここに直置きしない）
RULE — 公開 URL の不変性
public バケットに置いた key は公開後にリネーム・削除で URL を壊さないことを原則とする。差し替えは同一 key への上書き（CDN キャッシュは §7.2 の Cache Rule に従い最大 1 時間で追従）。廃止時は削除ではなく gone/ prefix へ移動し、四半期ごとに一括削除する。

5.4 CORS ポリシー（public バケットのみ）

    "AllowedHeaders": ["Range"],

  }

06. Mac 側構築仕様

6.1 インストール

brew install rclone
rclone version   # v1.68.0 以上であることを確認。満たさない場合 brew upgrade rclone
mkdir -p ~/R2/private ~/R2/public ~/Library/Logs/rclone

6.2 rclone リモート定義

rclone config の対話は使わず、設定ファイルを直接配置する（冪等・再現可能にするため）。Secret を direnv 等に置かず rclone.conf に書く場合、ファイル権限を 600 にする。

~/.config/rclone/rclone.conf
[r2]
type = s3
provider = Cloudflare
access_key_id = {{R2_ACCESS_KEY_ID}}
secret_access_key = {{R2_SECRET_ACCESS_KEY}}
endpoint = https://{{ACCOUNT_ID}}.r2.cloudflarestorage.com
acl = private
no_check_bucket = true
  • no_check_bucket = true: トークンにバケット作成権限がないため、rclone がバケット存在確認/作成を試みてエラーになるのを防ぐ。必須。
  • リモートは 1 定義で共用し、パスで r2:flab-stor-private / r2:flab-stor-public を切り替える。
  • 疎通確認はバケット名を明示して行う。バケットスコープのトークン（D-06）ではアカウント全体の ListBuckets（rclone lsd r2:）が権限不足で失敗またはリスト欠落し得るため、rclone lsd r2: を疎通判定に使ってはならない。
chmod 600 ~/.config/rclone/rclone.conf
rclone lsd r2:flab-stor-private   # エラーなく終了すること（空バケットなら出力なしで正常）
rclone lsd r2:flab-stor-public    # 同上
echo "hello" | rclone rcat r2:flab-stor-private/inbox/hello.txt
rclone cat r2:flab-stor-private/inbox/hello.txt   # "hello" が返ること
rclone deletefile r2:flab-stor-private/inbox/hello.txt   # 後片付け（削除権限の確認を兼ねる）

6.3 マウントコマンド仕様（正式版）

launchd から呼ぶ共通スクリプトとして配置する。フラグは以下を厳守（変更禁止。チューニングは §6.5 の許容範囲内のみ）。

~/bin/r2-mount.sh（chmod +x）
#!/bin/zsh
# usage: r2-mount.sh {private|public}
set -euo pipefail

PLANE="${1:-}"
if [[ "$PLANE" != "private" && "$PLANE" != "public" ]]; then
  echo "usage: r2-mount.sh {private|public}" >&2
  exit 2
fi
BUCKET="flab-stor-${PLANE}"
MOUNTPOINT="$HOME/R2/${PLANE}"
VOLNAME="R2-${PLANE}"

mkdir -p "${MOUNTPOINT}"
# 前回異常終了で残った stale mount を掃除（マウント中なら解除してから再マウント）
if mount | grep -q " ${MOUNTPOINT} "; then
  umount "${MOUNTPOINT}" 2>/dev/null || umount -f "${MOUNTPOINT}" 2>/dev/null || true
  sleep 1
fi

# --volname は nfsmount では無視される場合がある（無害なので付与したままとする）
exec /opt/homebrew/bin/rclone nfsmount "r2:${BUCKET}" "${MOUNTPOINT}" \
  --volname "${VOLNAME}" \
  --vfs-cache-mode full \
  --vfs-cache-max-size 10G \
  --vfs-cache-max-age 72h \
  --vfs-write-back 15s \
  --vfs-read-chunk-size 16M \
  --vfs-read-chunk-size-limit 512M \
  --dir-cache-time 60s \
  --poll-interval 0 \
  --attr-timeout 5s \
  --transfers 8 \
  --s3-chunk-size 64M \
  --s3-upload-cutoff 128M \
  --exclude ".DS_Store" \
  --exclude "._*" \
  --exclude ".Spotlight-V100/**" \
  --exclude ".Trashes/**" \
  --nfs-cache-handle-limit 1000000 \
  --cache-dir "$HOME/Library/Caches/rclone/${PLANE}" \
  --log-file "$HOME/Library/Logs/rclone/${PLANE}.log" \
  --log-level INFO

フラグ根拠（実装エージェント向け注記）

フラグ根拠
--vfs-cache-mode fullD-05。Finder のプレビュー生成・アプリのランダム I/O に必須。未指定だと nfsmount は実質読み取り専用相当の挙動になる
--vfs-write-back 15s保存後 15 秒でアップロード開始。連続保存（エディタ等）の重複アップロードを吸収しつつ、公開反映の体感遅延を許容範囲に収める
--poll-interval 0S3 系は変更通知ポーリング非対応のため明示的に無効化（警告ログ抑制）。外部変更の反映は dir-cache-time=60s に依存
--s3-chunk-size 64M / --s3-upload-cutoff 128M128MB 超をマルチパート化。動画・zip 等の大物で再送単位を適正化。Class A 回数とメモリのバランス点
--exclude 群K-04 の強制。Finder メタデータをバケットへ書かない
--vfs-cache-max-size 10Gローカルディスク使用上限。超過時は LRU で追い出し

6.4 launchd 常駐化

ログイン時に両プレーンを自動マウントし、プロセス死亡時に再起動する。launchd 配下では --daemon を付けない（フォアグラウンドで exec し launchd に監視させる。二重 fork すると KeepAlive が機能しない）。plist は private / public で 2 枚、差分は文字列 1 箇所のみ。

~/Library/LaunchAgents/dev.fracturelab.r2mount.private.plist（public 版は "private" を全置換）
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key>            <string>dev.fracturelab.r2mount.private</string>
  <key>ProgramArguments</key>
  <array>
    <string>/Users/{{MAC_USER}}/bin/r2-mount.sh</string>
    <string>private</string>
  </array>
  <key>RunAtLoad</key>        <true/>
  <key>KeepAlive</key>
  <dict>
    <key>SuccessfulExit</key> <false/>   <!-- 異常終了時のみ再起動 -->
  </dict>
  <key>ThrottleInterval</key> <integer>10</integer>
  <key>StandardErrorPath</key>
    <string>/Users/{{MAC_USER}}/Library/Logs/rclone/private.launchd.err</string>
</dict>
</plist>
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/dev.fracturelab.r2mount.private.plist
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/dev.fracturelab.r2mount.public.plist
# 停止・アンマウントは:
launchctl bootout gui/$(id -u)/dev.fracturelab.r2mount.private
umount ~/R2/private 2>/dev/null || true
Finder サイドバー登録
マウント後、Finder で ⌘⇧G → ~/R2 を開き、private / public をサイドバーへドラッグして固定する。ネットワークドライブとしてではなくローカルパス経由で常時見える状態が完成形。
CAUTION — Finder の「取り出し」との関係
Finder やコマンドで手動アンマウントすると rclone は正常終了（exit 0）するため、KeepAlive.SuccessfulExit=false の設定では自動再マウントされない（意図的な取り出しを尊重する設計）。再マウントは以下で行う: 
launchctl kickstart gui/$(id -u)/dev.fracturelab.r2mount.private

Finder メタデータ書込みの二重防御（推奨・一度だけ実行）

§6.3 の --exclude はバケット側への保存を防ぐが、Finder が書込みを試行すること自体を止めるため、ネットワークボリュームへの .DS_Store 生成を OS 設定で無効化する:

defaults write com.apple.desktopservices DSDontWriteNetworkStores -bool true
# 反映にはログアウト/再ログインが必要。exclude と併用する（どちらか一方に依存しない）

6.5 チューニング許容範囲

実装後の実測に基づき、以下の範囲でのみ変更可: vfs-cache-max-size 5–50G / vfs-write-back 5–60s / transfers 4–16 / dir-cache-time 60s–5m（§10 のコスト制約により 60s を下回る設定を禁止）。それ以外のフラグ変更は本設計書の改版を要する。

07. 外部公開レイヤ仕様

7.1 カスタムドメイン接続（恒久公開）

  1. R2 → flab-stor-public → Settings → Custom Domains → Connect Domain
  2. files.fracturelab.dev を入力（ゾーンが同一 Cloudflare アカウントにあるため、CNAME・TLS 証明書は自動発行される）
  3. Status が Active になったら https://files.fracturelab.dev/<key> で全オブジェクトが GET 可能
CAUTION
カスタムドメイン接続後、public バケットはキーを知っていれば誰でも読める状態になる。ディレクトリリスティングは提供されない（key の総当たりは不可能だが、秘匿性はキーの推測困難性のみに依存する）。機微なファイルは絶対に public バケットへ置かない。これが D-02（物理分離）の存在理由である。

7.2 Cache Rules（推奨設定）

Cloudflare ダッシュボード → fracturelab.dev ゾーン → Caching → Cache Rules で 1 ルール作成:

項目値
Rule namer2-files-cache
WhenHostname equals files.fracturelab.dev
Cache eligibilityEligible for cache
Edge TTLOverride → 1 hour（上書き反映の最大遅延 = 1h。即時反映したい場合はダッシュボードから該当 URL を Purge）
Browser TTLOverride → 4 hours

不変アセット（releases/ 配下等）はアップロード時にオブジェクトメタデータで長期キャッシュを付与できる: rclone copyto --header-upload "Cache-Control: public, max-age=31536000, immutable" ...（§8 の r2share pub --immutable が内部で付与）。

7.3 presigned URL（期限付き共有）

  • 発行: rclone link "r2:flab-stor-private/<key>" --expire 24h。rclone が SigV4 署名付き GET URL を返す。サーバ通信なしのローカル署名で即時発行。
  • 有効期限上限: 7 日（604800 秒）。それ以上の共有は public バケット経由とする。
  • 制約: URL のホストは {{ACCOUNT_ID}}.r2.cloudflarestorage.com 固定。カスタムドメインでは presigned を使えない（R2 の仕様）。失効前の無効化は不可（無効化したい場合は対象キーをリネーム）。

08. 共有 CLI（r2share）仕様

日常操作を 1 コマンド化する zsh スクリプト。Finder 操作 + このコマンドだけで全ユースケースが完結する。

8.1 コマンド仕様

コマンド動作
r2share tmp <file> [--expire 24h]ローカル or マウント上のファイルを share-staging/{YYYYMMDD}/ へコピー（既に private バケット上ならコピー省略）し、presigned URL を発行してクリップボードへコピー・標準出力
r2share pub <file> [--prefix assets] [--immutable]ファイルを flab-stor-public/{prefix}/{YYYY}/{ファイル名をslug化} へアップロードし、https://files.fracturelab.dev/... を出力・クリップボードへ。--immutable で Cache-Control: max-age=31536000,immutable を付与
r2share ls [prefix]rclone lsf --format tsp ラッパで public バケットの公開中一覧を表示
r2share gone <key>public の key を gone/{key} へサーバサイド移動（URL 廃止手続き、§4.4 RULE 準拠）

8.2 実装要件

  • 言語: zsh 単一ファイル ~/bin/r2share。必須依存は rclone と pbcopy。任意依存として exiftool（画像メタデータ除去、§8.3。brew install exiftool）。
  • slug 化: 拡張子を除くファイル名を小文字化・空白→-・[^a-z0-9._-] 除去。拡張子も小文字化する（例: Logo Final.PNG → logo-final.png、T-12 と対応）。結果が空になった場合は file-{unixtime}。
  • --expire: デフォルト 24h。指定値が 7d（604800 秒）を超える場合は presigned の仕様上限超過としてエラー終了（exit 2）し、r2share pub の利用を促すメッセージを出す。
  • public 側で同名 key が既に存在する場合は確認プロンプト（-f で強制上書き）。無確認上書きの禁止。
  • すべてのサブコマンドは実行した rclone コマンドラインを --verbose 時に表示する（監査可能性）。
  • exit code: 成功 0 / 引数エラー 2 / 前提ツール欠如（exiftool 未導入で除去対象画像を pub、§8.3）3 / rclone 失敗はその exit code を透過。

8.3 画像メタデータ除去（r2share pub のみ・SEC-08 の実装）

公開用画像には Exif（GPS 位置情報・撮影機材・シリアル番号等）が残留し得るため、r2share pub は以下を実施する:

  • 対象拡張子: jpg jpeg png tiff heic webp（大文字小文字不問）。対象外の拡張子は無加工でアップロード。
  • 処理: 一時ディレクトリ（mktemp -d）にコピーした複製へ exiftool -all= -tagsfromfile @ -Orientation -ICC_Profile:all -overwrite_original <tmpfile> を適用し、複製をアップロードする（元ファイルは変更しない）。処理後に一時ディレクトリを削除。-Orientation と -ICC_Profile:all の復元指定は必須（省略すると回転情報・カラープロファイルまで剥がれ、公開画像が横倒し・色崩れで表示される）。GPS・撮影日時・機材情報はこの指定でも除去される。
  • exiftool の解決: ${R2SHARE_EXIFTOOL:-$(command -v exiftool)} で行う（環境変数 R2SHARE_EXIFTOOL による差し替えを許可。T-16 のテスト容易性のため）。
  • exiftool 未インストール時: 対象拡張子であれば アップロードを中断して exit 3 し、brew install exiftool または --keep-exif の指定を促すメッセージを出す（警告のみで続行しない。無自覚な位置情報公開を防ぐため）。
  • --keep-exif: メタデータ除去をスキップする明示オプトアウト。指定時はその旨を出力に表示する。
  • r2share tmp（presigned・時限・非公開バケット）ではメタデータ除去を行わない（受け渡し先で原本が必要なユースケースを想定）。

13. 既知の制約・リスクと対処

ID事象対処 / 設計上の織り込み
R-01空フォルダが消える。S3 系は空ディレクトリの概念がなく、dir cache 失効後に空フォルダは Finder から見えなくなる仕様として受容。フォルダは中身と同時に作る運用。§4 のレイアウトを先に rclone mkdir ではなくファイル配置で形成する
R-02リネーム＝コピー+削除。大容量ファイルのリネームは時間と Class A を消費公開後 key 不変ルール（§4.4）+ 命名を置く前に確定する運用
R-03書込みは write-back（15s+転送時間）遅延で反映。書込み直後の Mac 強制電源断でキャッシュ中データが失われ得る「保存＝即クラウド」ではないことを利用者が認識する。重要ファイルはメニューバーやログで転送完了を確認（rclone rc vfs/stats は将来拡張）
R-04複数マシンからの同一ファイル同時編集で後勝ち上書き（ロックなし）単一利用者・実質単一編集端末の前提。同時編集用途には使わない
R-05presigned URL はカスタムドメイン不可・発行後の失効操作不可D-04 で許容。無効化したい場合は key をリネーム（旧 URL は 404 化）
R-06オフライン時はキャッシュ済みファイルの読取りのみ可。新規書込みはキャッシュに溜まり復帰後に転送されるが、長期オフラインは非サポート常時接続前提（§1.3）。モバイル運用は想定外
R-07スパースバンドル/Time Machine/Photos ライブラリ等、数万小ファイル+ランダム I/O 用途は性能・課金とも不適スコープ外（§1.2）。バックアップは tar/zip 化した単位で vault-backup/ へ
R-08rclone / macOS メジャーアップデートでマウント挙動が変わる可能性brew upgrade 後は T-02/T-03/T-06 を再実行してから常用する。FSKit 移行線は §3.1 NOTE
R-09r2.dev を有効化したまま忘れると想定外経路で公開が続くSEC-05。検証後即無効化をテスト手順に組み込み済み（T-07 はカスタムドメインのみで実施）
R-10--exclude 対象名（.DS_Store 等）への書込みが VFS 上で拒否され、Finder に散発的な権限エラーとして表示され得る§6.4 の DSDontWriteNetworkStores で書込み試行自体を抑止（二重防御）。それでもエラーが頻発する場合のみ exclude を外し、月次で rclone delete --include ".DS_Store" --include "._*" による掃除運用へ切り替える（設計書改版事項）
