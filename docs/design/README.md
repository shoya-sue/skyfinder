# SkyFolder — デザイン原本

**このディレクトリはデザインの原本置き場です。ビルドに直接使いません。**
ビルドに使う派生物は `scripts/make-assets.sh` が生成し、`SkyFolder/Assets.xcassets/` に置きます。

> 手作業で書き出した派生物をリポジトリに置くと、原本を更新したときに再現できません。
> 原本 → 派生物の変換は**何度実行しても同じ結果になる**必要があります（設計書 §8.6 の冪等性と同じ考え方）。

## 原本

| ファイル | 内容 |
|---|---|
| `icon.jpeg` | アプリアイコン。角丸の青いタイルに、白い線画で**フォルダ + 雲 + 上向き矢印**（ローカルのフォルダからクラウドへ上げる＝本ツールの機能そのもの） |

## 小サイズでの視認性（実測・設計書 M-10）

現物を 1024px に拡大してから各サイズを生成し、目視確認した結果:

| サイズ | 判定 | 見え方 |
|---|---|---|
| **16 × 16** | ❌ **使用不可** | 線画が完全に潰れる。フォルダの輪郭がかろうじて分かる程度で、**雲・上向き矢印・表情はまったく判別できない**。「青い四角に何かある」としか見えない |
| **32 × 32** | ✅ 判別可能 | フォルダ・雲・表情が読める（矢印は細いがぎりぎり見える） |

**→ 16pt 用に、線を太らせて要素を減らした別版が必要です。** 矢印か雲のどちらかに絞る、フォルダの輪郭のみにする等。
この別版は**メニューバーアイコン（A-06・16〜18pt）にも流用できる**ため、まとめて設計してください。

> 切り出し・拡大・各サイズへの展開は **macOS 標準の `sips` だけで実行できます**（`sips -c` / `-z` / `--cropOffset`）。
> `scripts/make-assets.sh` に外部ツールの依存は要りません。
> ただし **16pt 用の別版だけは自動生成できません**（別の意匠が必要なため）。これは原本としてこのディレクトリに置いてください。

### A-03 の前提は実測と食い違っていた（2026-08-31）

「すでに角丸が描かれている」としていたが、**実描画領域 903×903 の四隅は 2px 程度の反エイリアスのみで、
実質的に正方形**だった。四隅の実測色は `#E5F0F8` / `#EBF3F6` / `#E8F0F5` / `#ECF2F3` で、
2px 内側はすでにタイルの青（`#77A8CF` → `#6FB4EC`）になっている。

したがって「OS のマスクと二重になる」問題は起きない。
**deployment target が macOS 14 なので、macOS 11〜15 の従来方式**
（1024 のキャンバスに 824 の角丸正方形・半径 185.4）で描いている。
macOS 26 でも classic な AppIcon アセットは従来どおり描画されるため、両方で成立する。

### 暫定対応の記録

**A-01（2026-08-31 時点）**: 実描画領域 903×903 を 824×824 に**縮小**して 1024 キャンバスに配置している。
拡大ではないため線画のエッジは甘くならない。ただし原本が 1024px 以上の正方形で用意し直されれば
より鮮明になるため、G5-5 で差し替える対象として残す。差し替えは
`docs/design/icon.jpeg` を置き換えて `./scripts/make-assets.sh` を再実行するだけでよい
（描画領域は自動検出しており、位置を決め打ちしていない）。

### 16pt 用の別版について（A-04 / A-06）

設計書は「自動生成できない人間の作業」としていたが、**コードで定義**した
（`scripts/make-assets.swift` の `folderPath` / `arrowPath`）。
理由は §15.3 の再現性原則で、原本を差し替えたときに手作業の派生物だけ取り残されるのを避けるため。

意匠は「**塗りのフォルダから上向き矢印を抜く**」。線画ではなく塗りにしたのは、
M-10 のとおり 16px では線が完全に潰れるため。3 案（原本の縮小 / 矢印あり / 矢印なし）を
16px で生成して比較し、矢印ありを採用した。
